macOS direct area screenshot coordination, 2026-11-16

The synthetic native fixture starts an unfiltered area capture with no
registered windows and holds its completion. A protected window is registered
while the capture is in flight; its pending presentation remains blocked until
the capture completes. A second case checks that already registered and
explicitly excluded IDs are combined and dispatched to the filtered path. A
third makes that path throw and verifies the capture barrier is released.

The full scroll fixture, built as described in
screenshot-exclusion-barrier-20261116.txt, exited 0 and printed "direct
screenshot coordination: complete". Its opt-in live ScreenCaptureKit check was
skipped. The separate screenshot geometry test passed, and the full Swift daemon
typechecked for arm64 and x86_64 macOS 13.

The direct CGWindowList capture still runs on a background queue. When a daemon
window is already registered, the area capture uses ScreenCaptureKit exclusion
instead. A later change adds a Core Graphics window-list fallback when the
rectangle does not fit one display; see cross-display-window-list-20261116.txt.
The native AppKit tooltip is not registered by this change, and captured pixels
remain unverified.
