Known limits: a malformed legacy `.collecting` marker without a usable PID
still blocks opening because its owner cannot be checked safely. If an Electron
renderer crashes while its main process remains alive, its abandoned session
marker holds files until that process exits. PID reuse may also retain files
until the reused process exits. On Windows the Electron directory-sync helper
is a no-op; a missing marker can leave an orphaned file, and Windows runtime
durability and file identity were not exercised here. Invalid or missing saved
state prevents collection, leaving files in place rather than risking deletion.
If GPUI cannot record a candidate, it logs the error and preserves the file, so
that file may remain uncollected; Electron rejects the corresponding save/reset.
