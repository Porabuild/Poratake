macOS protected area capture spanning displays, 2026-11-16

The original direct area capture used the requested desktop rectangle with
CGWindowListCreateImage. The new exclusion path based on ScreenCaptureKit only
accepts a rectangle contained by a single display. If a protected daemon window
was registered, a cross-display direct capture would therefore fail.

When no single display contains the requested rectangle, the area capture now
obtains the on-screen window list, removes excluded IDs while retaining order,
and passes the original rectangle and best-resolution option to Core Graphics'
window-array image capture. Missing or malformed window metadata and an empty
remaining list fail closed. Single-display requests continue to use the
ScreenCaptureKit exclusion path.

The synthetic geometry test passed for a selection on a negative-origin
display, a rectangle crossing the display boundary, an empty display list,
ordered exclusion, maximum window ID, missing and malformed IDs, and an empty
filtered list. The read-only native metadata probe examined 15 on-screen window
IDs on this Mac and verified that filtering one preserved the order. It used:

The synthetic scroll/coordination fixture passed; the complete daemon typechecked
for arm64 and x86_64 macOS 13. No screen capture or privacy request was made.

This Mac has one active display. The tests do not establish the window-array
image's pixels, window compositing, color handling, transparency, or mixed-DPI
behavior. Core Graphics' window-image APIs are deprecated and marked obsolete
for macOS 15 in the current SDK; the existing direct path uses the same legacy
family. Verify the new fallback on an already-authorized Mac with multiple
