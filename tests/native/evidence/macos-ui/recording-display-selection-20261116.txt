macOS recording display selection, 2026-11-16

ScreenCaptureRecorder previously selected the first available display when an
explicitly requested display ID was absent from ScreenCaptureKit's display list.
That could start a screen or area recording on a different display after the
selected display disappeared. The selection now returns CONFIGURATION_ERROR in
that case, before removing the output path or creating an asset writer. If a
selected window has moved onto an available display, its current display still
takes precedence over the original display ID.

The native fixture exercises generated display IDs for a present selection, an
unavailable selection, a window moved to another display, a moved window whose
old display is unavailable, the default main display and an empty display list.
It also uses Core Graphics active-display metadata to check the current main
display and an unavailable ID. The test machine reported one active display.
The old fallback failed the unavailable-selection assertion. The fixture does
not request Screen Recording access or start any capture.
