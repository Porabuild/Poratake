macOS GPUI video redaction crop investigation, 2026-11-16

The generated crop fixture composes a striped video over a translucent gradient
with rounded corners, a filled rectangle, overlapping fractional pixelation and
blur, and a later rectangle. A source-resolution crop with sufficient surrounding
pixels matched the corresponding full-composition pixels in the tested region.
Drawing that crop at half size matched the full composition scaled to half size
in the tested region, where the directly scaled preview differed. The crop is a
test experiment and is not used by the app. It does not establish correctness for
other crop boundaries, zooms, device frames, cameras, text, scaled exports, or
live recordings.

Run the functional fixture with:
cargo test --offline --locked --manifest-path src/main/Cargo.toml -p poratake-gpui source_resolution_crop_preserves_overlapping_video_redactions -- --nocapture

Run the synthetic timing with:
cargo test --offline --locked --manifest-path src/main/Cargo.toml -p poratake-gpui source_resolution_redaction_crop_timing -- --ignored --nocapture

On this Mac, one 3840x2160 solid generated frame with an 800x600 pixelation
region was composed eight times per mode; the first run was discarded. Before
the optimizations, median times were 5.22 ms for a 960x540 direct preview,
9.36 ms for an 832x632 source crop, 2.56 ms for an unredacted crop, and
41.63 ms for full composition. After exact aligned-block averaging and filling
repeated samples in runs, the corresponding medians were 4.91, 6.84, 2.54 and
38.63 ms. The preview and crop would both be needed in a crop-based design.
Decode, uploading, interaction, playback scheduling and slower hardware were
not measured. These results do not establish a real-time frame rate.

Drawing the reduced pixelation image directly was rejected: the existing
nearest-boundary test failed at a block transition. The adopted path preserves
the existing block mapping; generated checks cover multiple sizes, aligned and
fractional averaging, as well as screenshot and video pixelation. The generated
edited-video test also saves/reopens the project and compares its H.264 export
with the preview. The separate scaled-preview mismatch remains open.

An isolated dark 1280-point, 1x GPUI development parity run with a fake daemon
also passed its generated screen, area and window recording handoffs and decoded
zoom-export checks. That workflow does not exercise the crop prototype or a
live recorder.
