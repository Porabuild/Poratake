macOS protected tooltip during an area recording, 2026-11-17

The current daemon sources were compiled into a temporary test daemon. Its
screen-recorder start handler first called CGPreflightScreenCaptureAccess and
rejected a denied result. A validation-only request without an output path
confirmed that preflight passed before a recording was started. The temporary
daemon rejected microphone, camera, system audio, keyboard and iOS requests;
ScreenCaptureKit audio and cursor event monitors were disabled, and freeze
prewarm was a no-op. The production tooltip panel, capture-window registry and
ScreenCaptureKit filter update code were unchanged. No privacy setting was
changed or access request made.

A separate generated blue window covered the selected area. The daemon recorded
583x433 points at 2x, producing the video-only H.264
[movie](native-tooltip-exclusion-area-20261117.mov): 1166x866 pixels, 23 frames,
7.653 seconds. After the stream started, `recording-control.setTooltip` returned
`visible: true` for Start recording. The macOS window list showed the protected
panel at (929,456), 100x22 points, layer 1001. A separate green timing marker
was then shown and the window list still contained the protected panel. The
[RPC and window report](native-tooltip-exclusion-area-20261117.json) records the
sequence and measured bounds.

The seven decoded frames at 1.908–2.917 seconds contain the green marker. A
280x124-pixel region surrounding the protected panel's 200x44-pixel bounds was
byte-identical to the baseline frame in every one of those frames: mean and
maximum RGB difference were both zero. The [protected-frame image](native-tooltip-exclusion-protected-20261117.png)
shows that result.

After hiding the tooltip, the fixture displayed an unprotected magenta panel at
the same bounds and layer. It appeared in the decoded movie at 4.225–5.233
seconds; the [positive-control image](native-tooltip-exclusion-positive-20261117.png)
shows the green marker and the magenta panel. A stable positive-control frame
contained 8,800 magenta pixels, exactly 200x44. This confirms that the recording
included that screen location and that an ordinary window at the same bounds
was captured. Outside the marker and tooltip regions, every decoded frame was
identical to the uniform blue baseline. The movie SHA-256 is
`079cb72c7c75024d38c8f3a30db74d15ba6fc327196781f89ed6c0bca383b461`.

This is a direct daemon RPC area-recording check, with audio and input tracking
disabled in the temporary daemon. It does not prove the full GPUI recording
handoff, screenshot exclusion, window or full-screen targets, other displays,
or unpressed physical hover. The generated windows and temporary daemon exited;
the existing editor remained open.
