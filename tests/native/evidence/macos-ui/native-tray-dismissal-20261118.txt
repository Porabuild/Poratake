macOS native GPUI tray menu dismissal, 2026-11-18

Native development probe on one built-in Retina display. The fixture
supplied app-local status-bar rectangles at the left and right edges,
toggled the normal tray menu, and dispatched app-local Escape.
A previously authorized screen-only daemon photographed only the
temporary menu window by ID. No physical mouse or keyboard takeover
or new permissions were used.

Each build and appearance ran six openings, alternating right with
Escape dismissal and left with toggle dismissal. Both variants
settled to 304×564 points with x=8 or x=1416 and y=41. All 60
window captures per variant measured 608×1128 pixels. The visible
menu used the expected row layout and shortcuts. Some frames had
different opacity while the menu was appearing. Pixel observations
do not establish the first compositor presentation timestamp.

First openings are omitted from the warm calculation. The probe
includes input dispatch and WindowServer sampling. The fixed Escape
path keeps the explicit 100 ms menu animation and avoids the native
window's additional exit transition. A trial that switched native
animations off on window creation was discarded after premature
deactivations. The final change applies at dismissal only.

A separate dark run sent Escape, toggle, and reopen as one input burst.
The replacement kept its window ID after the previous menu's delayed
close callback and subsequently dismissed on Escape. All 1,173 runnable
GPUI tests and 70 Electron menu and tray reference tests passed.
