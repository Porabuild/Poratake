Native GPUI window screenshots after a target change, macOS, 2026-11-18

Single built-in Retina display, isolated GPUI development profile,
disposable AppKit window, previously authorized screen-only daemon.
The native list supplied the actual ID and bounds of the disposable
window. The bridge limited displayed candidates to that window, and
app-local events picked it. The selector closed before the bridge
released the capture request. The target then moved, resized and
changed color, or closed, as indicated below.

The live request used capture-window with the same window ID after
the new window geometry was confirmed in WindowServer. Frozen

bounds. In both modes the saved image opened in the preview and
editor, and the frozen screen cleared after capture. Pixel comparison
used ColorSync conversion to sRGB.

after the final error arrived. Rust coverage also verifies that a
nonempty stage survives a definitive error and that an ambiguous RPC
timeout retains even an empty stage because the daemon could still
write. All 1,172 runnable GPUI tests and the light and dark timer workflows passed.
The 71 Electron reference tests also passed, including exclusive
publication and temporary screenshot cleanup. This comparison uses
Electron's reference tests. It does not drive an Electron window picker.
