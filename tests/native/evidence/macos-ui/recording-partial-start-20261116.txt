macOS GPUI parity fixture, isolated profile and generated video

The fake daemon writes a generated movie to the requested project and then
returns START_FAILED. Before the change the movie had been deleted; the fixture
failed while trying to read it. After the change, light and dark runs confirm
the movie is byte-identical, the warning names its project, the overlay is
cleared and the controls can retry. A separate explicit rejection with no media
still removes its empty project.

Real-filesystem tests also retain empty project directories for an uncertain
timeout or daemon disconnect. They do not simulate a live daemon continuing to
start after the timeout; that lifecycle remains unresolved.
