macOS recording toolbar tooltip handoff, 2026-11-18

GPUI development build at 8a787371, built-in Retina display, isolated
native UI probe, temporary profile and generated preview. Both light
and dark used the same sequence of app-local unpressed mouse-move events.

Start recording
Select camera
Select microphone
Turn system sounds on
Select iPhone or iPad
Close

The driver traversed the six actions in both directions. For each move,
the requested tooltip matched the target and the number of painted
inline keyboard labels was zero. Consecutive moves sent as a burst
ended with Close forward and Start recording backward. Pointer exit
cleared the native tooltip request and restored one inline keyboard
label on the already focused control.

The GPUI probe observes the outgoing tooltip request and inline paint.
The Swift AppKit fixture independently checks native panels. It stages
Camera and Microphone over one toolbar while an in-flight screenshot
holds their visibility barrier. Earlier panels are transparent and all
three window IDs are retained in the capture exclusion registry until
the screenshot completes. A late Hide for the previous control is
rejected. After release, only Microphone is visible, with the current
appearance, inside the work area, clear of the toolbar and farther along
the pointer path than Camera. The old window IDs then retire. Sending
the current Hide clears the remaining exclusion.

The full optimized Swift fixture checks this case in Aqua and Dark Aqua
on arm64 and under x86_64 Rosetta. The test uses a synthetic screenshot
barrier and AppKit windows, with no live capture or pointer takeover.
Physical mouse delivery and mixed-display placement were outside this
probe.
