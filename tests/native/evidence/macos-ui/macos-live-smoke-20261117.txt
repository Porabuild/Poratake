Follow-up, 2026-11-17

Permission and capture
- `native-permission-status-onboarding-20261117.png` shows Screen Recording and Accessibility granted for the GPUI development app. No privacy setting changed and no permission dialog appeared.
- A real full-screen take decoded as H.264, 3456x2234, 199 frames, 19.987 seconds. The saved screen contained macOS notification banners and a purple system status dot, but no Poratake recording controls or capture overlay. The frame was left in the scratch directory because the notifications are unsuitable repository evidence.
- A real preselected area take of the generated QuickTime pattern decoded as H.264, 1216x720, 179 frames, 29.145 seconds. Its decoded frame contains only the generated pattern and embedded timecode, without capture controls or selector UI.
- A real window take followed the generated QuickTime window from `(108,141)` to `(250,220)` and decoded as H.264, 1280x720, 1590 frames, 159.773 seconds. Its decoded frame contains only the test pattern. A second take finalized after the generated QuickTime target process closed: H.264, 1280x720, 1592 frames, 160.083 seconds. Both takes preserved their recorded content.
- An area recording with `PORATAKE_NATIVE_SMOKE_SYSTEM_AUDIO=1` captured a generated 997 Hz tone. The `system.m4a` sidecar is AAC, 48 kHz stereo, 29.163 seconds; the 997 Hz signal is present from 10.5 to 13.5 seconds. No microphone or camera was enabled.

Editor and export
- The existing `drawing_tool_ui_edit_survives_reopen_and_matches_export` GPUI editor test used each real captured movie, applied a drawing edit, saved and reopened the editor project, exported, decoded the output, and compared it with the reopened preview. It passed for screen, window, and area inputs.
- Mean preview/export channel error was 0.92/0.38 at the first/later screen frames, 0.69/0.40 for the window-close take, and 0.77/0.38 for the area take. The area export retained the generated 997 Hz tone in its AAC track.
- The native Export Video button opened the Save sheet, but the background computer-control helper could not target that AppKit sheet. The actual Save-button interaction remains unverified; the editor's direct export path passed with the same captured recordings.
- Area and window source frames, editor previews, decoded export frames, and metrics are retained in `video-recording-editor-smoke-20261117/`. The full-screen recording evidence remains temporary because it contains OS notifications.
