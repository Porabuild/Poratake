macOS timer control lifecycle — 2026-11-16

Built the production TimerControlModule, FloatingPanel and TimerButton with a
fixture providing mocked daemon transport. Positions came from the isolated
GPUI edge-placement probe on this Mac's 1728-point primary display. The fixture
showed the actual panel, sent constructed AppKit mouse events to cancel it,
waited for a one-second countdown, then showed and explicitly hid the panel.
Each event and hide response checked that no timer panel remained visible.
The fixture restored the previously frontmost application when it still owned
focus. It did not capture the screen or access media devices.

Command:
swiftc src/main/daemon/UI/Theme.swift src/main/daemon/UI/FloatingPanel.swift \
  src/main/daemon/UI/TimerButton.swift src/main/daemon/Core/DisplayCoordinates.swift \
  src/main/daemon/Modules/TimerControlModule.swift tests/native/timer-control-lifecycle.swift \
  -o /tmp/poratake-timer-control-lifecycle
/tmp/poratake-timer-control-lifecycle 0 128 1588 128

Result (exit 0):
left visible at x=0 y=128 size=140x52
cancel: timer hidden
right visible at x=1588 y=128 size=140x52
completed: timer hidden
cleanup visible at x=0 y=128 size=140x52
hide: timer hidden

This does not test physical pointer input, live GPUI-to-daemon communication,
actual timer capture, another display, or the pixels in a saved capture.
