macOS recording stream errors during startup, 2026-11-16

The ScreenCaptureKit delegate previously ignored an error from the current
stream while the recorder's start operation was still in progress, because its
public state remained idle until startup completed. This could drop a window
target-closed event before the module's startup handoff. The callback now also
accepts errors for the current stream and session while startup is active.

The native fixture invokes the same callback handler without creating a stream
or starting capture. Before the fix it failed because the startup error was not
reported. Afterward it checks the current session ID and TARGET_CLOSED mapping,
an ordinary display-source failure, normal recording errors, stale streams
and an inactive session. It does not exercise a real ScreenCaptureKit delegate
or prove that an OS callback occurs at a particular time.
