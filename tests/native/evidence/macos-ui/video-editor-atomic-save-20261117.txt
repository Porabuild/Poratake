GPUI video editor state persistence, macOS, 2026-11-17

Video editor state previously overwrote state.json in place. GPUI now writes a
new, exclusively created sibling file, syncs it, replaces the old state, and
syncs the containing directory on Unix. Windows uses the existing replacement
operation with write-through; it was not run on this Mac. A failed save does
not update the editor's saved timestamp. On orderly GPUI editor closure, a
pending debounced state is saved before the editor is dropped.

Temporary-file tests checked replacement, preservation of an existing target
when replacement fails, removal of temporary files, and readers seeing only
complete versions while repeated writes ran. An isolated GPUI test forced a
save failure and checked that the saved timestamp did not advance. Another
removed a generated music track, undid the removal, immediately closed before
the debounce, then reopened state.json and verified both the track and its
file. The 17-test music selection also passed with two ignored; the generated
WAV reimport/preview test passed separately using the installed FFmpeg.

This verifies orderly close and the file replacement contract, not a physical
power-loss test. Electron's separate persistence path and safe collection of
retired music files still require work. File syncing occurs during GPUI save;
its effect on interactive latency for slow filesystems was not measured.
